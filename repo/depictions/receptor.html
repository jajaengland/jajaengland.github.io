Background desktop management (1.8.0b1)

Update both Receptor and the Windows companion to 1.8.0 beta 1. On Windows, enable Allow background device access, Start sharing and open Manage device. In Receptor → Desktop, connect/refresh, then open Background desktop access, compare the PC key and enable it once.

The PC can manage sources and packages with reviewed APT dependency plans, inspect the operation log, request a confirmed respring and browse/upload/download regular files in Receptor’s download folder while the iPad app is closed. The full Filesystem tab is not remotely exposed. Close Cydia before package changes. APT uses system networking and certificates.

The explicit grant permits unattended package changes while locked and persists across app closure/reboot. A root service makes outgoing encrypted, authenticated requests to the pinned PC, with no listening port on the iPad. Disable background access or Forget saved connection on-device to revoke it; Reset pairing on Windows replaces the PC key and revokes old grants. Already dispatched operations may finish after disconnecting: check the operation log before retrying an uncertain install.

Keep Windows running and sharing enabled and the device powered and reachable on private Wi-Fi. Sleeping/locked Wi-Fi depends on iOS and power state. Background launchd, permissions and APT behavior still need physical-device testing. Legacy Add files / Send to PC uses authenticated but unencrypted HTTP; Manage device file transfers use encryption.

Packages tab (1.7.0b1)

Manage sources, search package names, view installed tweaks and preview dependency changes before installing/upgrading or removing packages inside Receptor. Requires the device’s apt7 or compatible apt command-line tools. Fully close Cydia before changes and keep Receptor open. APT uses its own TLS/HTTPS methods; Receptor’s bundled download transport is separate. Real device package/source operations still need testing.

Add flat HTTP(S) sources with +, refresh indexes, then search. Source removal preserves installed packages. Recognized Cydia metadata is synchronized, with a private backup. Unknown metadata layouts are refused. Install/remove plans are checked again before applying; protected system components cannot be removed. Normal authentication is default; unsigned legacy packages require an explicit separate per-install warning. No automatic respring. Windows remains beta 2.

Packages beta release and testing notes

Manual respring (1.6.0b3)

Use Respring in the Files toolbar or Install Log, then confirm. Finish transfers and close Cydia first. Receptor blocks its own active installations/downloads and checks the dpkg lock. This is a manual Home/lock-screen restart, not a reboot. It never runs automatically on install, app launch or boot, and does not automatically detect which packages require it. Cydia is accessible from the Install Log toolbar. The fixed helper restart path needs physical-device validation. Windows stays at 1.6.0 beta 2; saved pairing is unchanged.

Two-way transfers and filesystem browser (1.6.0)

Upgrade Receptor to 1.6.0b3 and the Windows companion to 1.6.0 beta 2. Saved pairing is kept. On the PC, enable Receive files sent from the device, choose a folder, and keep sharing running. Beta 2 allows this without stopping sharing or disconnecting. The address/code remain visible when paused; click Start sharing before connecting. On the device, hold a file or tap ••• → Send to PC, then tap Send. Keep both apps open until delivery is verified. Use Open folder on Windows to find received files.

The separate Filesystem tab starts at /, includes hidden files, and offers folder navigation, Quick Look preview and Send to PC for readable regular files. It is read-only and uses the app’s existing permissions; protected paths may be unavailable. Filesystem browsing/export does not use the privileged helper. Special files are excluded. The Files tab retains download management, grid/list and installation.

Uploads use authenticated metadata, SHA-256 verification, signed receipts and no-overwrite saving. Receiving is opt-in; only selected files are exported. Local HTTP is not encrypted. Preparing a device snapshot needs additional free space. Up to 32 incoming files per session, each at most 2 GB. A fully delivered copy can remain after a cancelled/lost receipt. New iOS UI and iOS 7–8 adapters need physical-device tests.

Experimental iOS 7–8 support

1.5.0 adds a guarded iOS 8 WKWebView adapter and workspace IPA installer, retaining the legacy iOS 4–7 paths. Safari downloads on iOS 7–8 open Receptor and ask for in-app Download confirmation. Public HTTP(S) GET links are supported; private cookies/headers, POST bodies and one-time responses are not transferred. iOS 7–8 behavior is not yet device-validated. arm64 Safari is not included. Older Windows companions and saved pairing remain compatible for PC-to-device transfers. Older 1.4.1 files remain available for iOS 4–6.

Beta release and device test instructions

Features

  • 1.4.1: Safari profiles/certificates use the native installer; direct Catbox downloads have a default User-Agent. Certificate checks stay enabled.
  • Save supported images/videos to Photos. Share uses the system sheet on iOS 6 or a legacy menu on iOS 4–5; Open In remains a separate compatible-app picker.
  • Transfer any file type from Windows, including empty and extensionless files. Up to 32 files per session, each at most 2,147,483,647 bytes.
  • Adaptive grid or list with filename search, image thumbnails, zoomable image preview and Open In sharing to compatible installed apps. Legacy preview formats and memory limits apply.
  • Pair with Receptor Desktop over Wi-Fi and receive files without Safari. Transfers authenticate the peer and file contents; local HTTP is not encrypted. Legacy transfers require on-device installation confirmation; opt-in background management uses desktop confirmation.
  • Download prompts for file links and unsupported content in Safari.
  • Up to three simultaneous downloads, progress display and cancellation.
  • Files saved in /var/mobile/Media/Receptor/.
  • Quick Look previews, document interaction and file deletion.
  • Completion alerts and finite background execution.
  • A standalone Home screen app with direct URL downloads.
  • Bundled modern TLS with current CA roots and certificate verification.
  • Install saved IPAs through the legacy iOS installer, after confirmation.
  • Install saved DEBs through dpkg, view installation output, and manage them in Cydia.

Requirements

Rootful jailbreak, Cydia Substrate, 32-bit iOS 4.0–8.x and an armv7 device. Safari must be allowed to write to the Receptor directory.

Using Receptor

Tap a downloadable link in Safari and choose Download. Open Receptor from your Home screen to see active transfers or saved files. Tap + to paste a file URL. Tap an IPA or DEB and choose its Install action. Swipe a transfer to cancel it, or a saved file to delete it.

DEB installation

Close Cydia before installing a DEB. Confirm the selected package; its scripts run as root. Successful installs appear in Cydia's Installed list after reopening it. Use Install Log for errors and Cydia to install missing dependencies. Receptor does not force an incompatible package or remove package-manager locks. Respring if the package requires it.

Desktop transfers

Upgrade both apps to 1.6.0 for transfers in both directions. Start sharing in ReceptorDesktop.exe on Windows, add files, then open Receptor → Desktop. Enter the address and short code shown on the PC once. Receptor saves the pairing and reconnects next time you open Desktop. Tap any file to receive it, then return to Browse to preview or use the file menu → Open In. DEB/IPA installation remains a separate confirmed action. Forget saved connection removes the iOS record; stop sharing and Reset pairing on the PC revokes remembered devices. Keep both apps open on the same private Wi-Fi network. Permit private-network firewall access on Windows if asked. Tap Install on the iPad and check Install Log afterward. This new flow still needs physical-device testing.

Limitations

Downloads use HTTP(S) GET requests. There is no resume after the owning process exits. Keep the app that started a long download in the foreground. Receptor's TLS update does not change Safari's webpage networking or Cydia's repository networking. Unsigned IPAs may require a compatible AppSync setup. FairPlay authorization and device/iOS compatibility still apply.
